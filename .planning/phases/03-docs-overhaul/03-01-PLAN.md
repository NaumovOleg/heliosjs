<objective>
Follow-up documentation pass, ~11 days after a prior full overhaul (build fixed, ~40
accuracy bugs fixed, content gaps filled, UI redone — see
[[helios-docs-overhaul]] memory). This plan is scoped from two fresh audits (one
content-gap, one accuracy — both run today against current source, see the
"Findings" section below) plus the user's explicit asks: fix consistency, add more
examples/use-cases and "why" explanations, verify every claim against reality, and
rewrite the landing page to clearly state why a user should pick Helios over
Express/Fastify/NestJS — bringing the docs toward "production-grade + marketing"
quality.

The accuracy half of the audit (stale benchmark numbers, a stale linear-scan
rationale, README's empty version column and wrong "DI" claim) is ALREADY FIXED —
see commit `4a1c0ec`, done same session before this plan was written. This plan
covers what's left: the landing page rewrite and the content-gap findings.

Purpose: a framework's docs are itself a sales pitch for evaluators, and right now
the pitch is incomplete in two specific, fixable ways — (1) the actual homepage
(`src/pages/index.tsx`) and `intro.md` never once mention a competing framework or
link to the benchmarks that already exist and already favor Helios in several
dimensions, so a first-time evaluator's actual question ("why not just use X") goes
unanswered even though the evidence is sitting one click away; (2) large parts of
the reference docs (core-module, http-module, aws, azure, grpc) never got the
Purpose/Remarks/Related structural treatment that middlewares/ already has, so
they read as syntax dumps rather than a considered guide.

Output: a rewritten homepage and intro "why Helios" section, cross-linked and
security/composition-complete gRPC docs, a real grpc/api.md, a de-duplicated
error.md/catch.md pair, one realistic composed-middleware example, and Related
sections wiring the doc set together.

## Findings this plan is built on (verified this session, don't re-derive)

**Content-gap audit, ranked (full detail in that agent's report, not repeated here):**
1. `intro.md`/homepage never mention Express/Fastify/NestJS or link to benchmarks.
2. gRPC docs (all 4 files) never mention `credentials`/TLS despite it being a real,
   warned-about-by-the-logger config option; gRPC has no guard/RBAC equivalent and
   no doc says so explicitly.
3. 19/34 doc files have zero outbound cross-links; core-module/http-module/aws/
   azure/grpc mostly lack the `## Related` section middlewares/ already has
   (middlewares: 10/10 Purpose, 10/10 Remarks, 4/10 Related — everyone else: 0
   Purpose except benchmarks' own format, patchy Remarks, near-zero Related).
4. Zero doc file anywhere combines `@Guard` + `@Pipe` + DTO validation, despite
   `request-lifecycle.md` documenting the pipeline order that makes it meaningful.
   `pipe.md`/`sanitize.md` specifically never compose with validation even though
   their own Remarks sections say they should (piped-then-validated,
   sanitized-then-validated).
5. `grpc/api.md` (74 lines) is a bare export list, zero real per-item usage.
6. `http-module/graph-ql.md` doesn't document the `playground` option (listed in
   `server.md`'s own config table), no error-handling pattern, no guard/roles
   interaction story, no Purpose/Remarks/Related.
7. `core-module/error.md` duplicates most of `middlewares/catch.md` instead of
   linking to it; catch.md's actually-unique content (async handlers, factory
   pattern) isn't surfaced from error.md.
8. Purpose section missing from: controllers.md, error.md, installation.md,
   parameter-decorators.md, rate-limiting.md, validation.md, server.md,
   websockets.md, server-sent-events.md (and all of aws/azure/grpc).
9. gRPC's missing guard/RBAC story reads as an oversight, not a documented
   boundary — should be an explicit callout, not silence.
10. Frontmatter inconsistent (`description:` vs `sidebar_position`, split by
    directory) — cosmetic, lowest priority, fold into whichever task touches a
    given file rather than a dedicated pass.

**Already fixed this session (commit `4a1c0ec`, don't redo):** benchmarks.md's
stale 2026-09-11 numbers, benchmarks-middleware.md's pre-trie linear-scan
rationale, README.md's empty version column and "DI" claim.

**Thinnest files, worst-first (for prioritizing task order below):** grpc/api.md,
http-module/graph-ql.md, grpc/{module,usage,examples}.md (heavy overlap),
aws/azure plugins.md, core-module/controllers.md, middlewares/cors.md,
core-module/error.md, intro.md (short by design but missing the competitive
framing specifically).
