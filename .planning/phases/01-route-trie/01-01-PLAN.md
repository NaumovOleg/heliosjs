<objective>
Replace the linear route scan in `findRoute` (`src/core/src/utils/core/match.ts`) with a per-root
segment trie used as a candidate index, keeping the legacy matching rules as the arbiter so
behavior is identical by construction.

Purpose: today every request walks all routes in declaration order, so a route's position in the
table is a tax (documented in the comment at the top of `benchmarks/servers/helios-middleware.ts`
and in CONCERNS.md "Route matching now scans the whole controller subtree"). Make lookup cost
depend on path depth, not table size.

Output: trie-backed `findRoute`, a differential test proving parity, a route-scale benchmark with
before/after numbers, a patch changeset.
</objective>

## Design (decided — do not re-litigate)

1. **Segment trie, not char-level radix.** Path routing gains nothing from splitting inside a
   segment; params/regex work per segment anyway. Same asymptotics as find-my-way.
2. **The trie is a candidate index; the legacy rules stay the judge.** Collect candidates from the
   trie, pick the winner with the *existing* rule (highest `specificity`; equal → lowest declaration
   order; method via `isMethodMatch`), and confirm the winner with the existing
   `matchCompiledRegex` — which also produces its params. Consequences: no positional param
   extraction, no per-node param names, a trie false-positive is filtered by the regex, and parity
   is by construction rather than by re-deriving priority rules.
3. **Only exactly-indexable routes go in the trie.** Eligible: `route.compiledRegex` set AND every
   non-empty segment is static, `:name`, or (last segment only) `x?` / `*`. Everything else goes to a
   `residual` list evaluated linearly with legacy logic: `:name(regex)` segments (compiled regex is
   not anchored per segment, so `:p(.*)` can span segments — a per-segment trie would differ),
   mid-route `*` or `?`, and hand-built routes without `compiledRegex` (they use the
   `extractParamsAndWildcard` fallback, a different implementation).
4. **Classify segments in the same precedence as `compileRouteRegex`:** `*` → `:n(re)` → endsWith
   `?` → startsWith `:` → static. (Note: a non-`:` segment ending in `?` is treated as optional
   there; mirror it.)
5. **Build lazily** on first lookup, cached in `WeakMap<ControllerMeta, Index>` keyed by the root
   meta (no test or src code mutates `routes` after construction — verified by grep). Flatten in
   the same DFS order as legacy (`controller.routes`, then `children`) and record declaration order
   in a local `Map<Route, number>` — do not add fields to `Route`.
6. No new dependencies. Keep `matchRoutes`, `findRoute`, `routeSpecificity`, `extractRouteParams`
   signatures and exports unchanged.

Node shape and lookup:

```
Node = { children: Map<string, Node>, param?: Node,
         exact: Route[],      // routes ending exactly here
         optional: Route[],   // last segment `x?` hanging off this node
         wild: Route[] }      // last segment `*` hanging off this node

lookup(segs):  // segs = normalizePath(path) split on '/', empties dropped
  walk(node, i):
    if i == segs.length: candidates += node.exact + node.optional(skip) + node.wild(zero)
    else:
      if i == segs.length-1: candidates += node.optional(consume one)
      candidates += node.wild                       // any remainder
      walk(node.children.get(segs[i]), i+1); walk(node.param, i+1)
  ∪ residual → keep legacy rule: candidate beats best iff specificity > bestSpec, or equal and
  order < bestOrder; must pass isMethodMatch and matchCompiledRegex !== null.
HEAD with no hit → repeat with method 'GET' (unchanged).
```

## If the differential test fails, look here first

1. Tie-break: `ANY` vs `GET` on the same path, and order across `children` (must be legacy DFS order).
2. Classification of non-`:` segments ending in `?`, and precedence against `:n(re)`.
3. `wild` zero-segment case (`/files/*` must match `/files`) and `optional` skip/consume boundaries.
4. HEAD→GET second pass reusing state from the first.
